# hh-autopilot

Локальный инструмент для поиска работы на hh: собирает вакансии под портрет
кандидата из `resume-site/data/resume.yaml`, считает объяснимую оценку
соответствия, готовит письмо и кладёт отклик в очередь ревью. Одобренные отклики
уходят на hh через браузерный интерфейс с окном, лимитом и остановкой по капче.

**Автоматическая отправка откликов выключена по умолчанию** и включается только
человеком на ограниченное время. Капча — остановка со статусом `needs_human`,
а не обход.

## Запуск

```powershell
pnpm install
Copy-Item .env.example .env   # один раз, локальные настройки
pnpm db:reset                 # схема базы одной командой
pnpm dev                      # http://127.0.0.1:3000
```

`pnpm db:reset` удаляет `data/hh-autopilot.db` и накатывает миграции заново.
База и `.env` в git не попадают.

### Если install падает на скачивании движков Prisma

`ECONNRESET` от `binaries.prisma.sh` при `--tls-max-v1.2` лечится: Node 26 по
умолчанию предлагает TLS 1.3 с гибридным post-quantum ключом, и не каждый край
CDN это принимает. Установка с явным потолком TLS проходит:

```powershell
$env:NODE_OPTIONS='--tls-max-v1.2'
pnpm install
```

Это ограничение машины и канала, а не проекта: в скрипты оно не зашито.

## Портрет кандидата

Портрет — подмножество `../resume-site/data/resume.yaml`: роль и опыт, навыки,
зарплата, форматы, `hh.portrait` и `hh.keywords`. Источник правды один — файл
резюме; в проекте живут только zod-схема нужных блоков и загрузчик, копии данных
нет. Путь по умолчанию — соседний пакет, `RESUME_PATH` в `.env` перекрывает его.

## Сбор вакансий

```powershell
pnpm hh:collect                              # 4 запроса из портрета, по 1 странице
pnpm hh:collect --query "Nuxt разработчик"   # сузить до одного запроса
pnpm hh:collect --pages 3                    # глубже по выдаче
pnpm hh:fixture "Nuxt разработчик" nuxt      # снять выдачу в HTML-фикстуру
pnpm hh:apply --dry-run                      # что и куда отправил бы, без нажатий
pnpm hh:apply --limit 1                      # живой прогон не больше одного отклика
pnpm hh:apply:fixture 138950534 vacancy --form  # снять страницу вакансии и форму
```

Сбор только читает выдачу: поиск по региону и форматам из портрета, разбор
карточек, сохранение в SQLite без дублей по `hhId`, повторный сбор обновляет
изменённые вакансии по отпечатку карточки. В карточке списка hh нет занятости,
даты публикации и описания — эти поля остаются пустыми до отдельных волн.

Сессия — профиль Playwright `HH_PROFILE_DIR` (по умолчанию
`../resume-site/.dsh/hh-profile`). Капча или истёкшая сессия — остановка с
сообщением, нужен человек; никакого обхода капчи в проекте нет.

## Скоринг

```powershell
pnpm hh:score                 # оценить все вакансии в базе
pnpm hh:score --threshold 75  # сменить порог отсечения и пересчитать
```

Веса критериев (сумма — 100): стек 35, роль и домен 25, формат и занятость 15,
опыт 15, зарплата 10. Порог отсечения по умолчанию 65 и живёт в настройке
`score.threshold`. Оценка объяснимая: у каждого критерия есть вес, заработанные
баллы и причина — они пишутся в `Score.criteria` и показываются в очереди ревью.

Правила, которые стоит знать:

- стек — полный балл с трёх совпавших технологий портрета, одна-две дают долю;
- роль и домен — слово роли и профиль из заголовка резюме; домен проверяется по
  описанию вакансии, а из выдачи описание не приходит, поэтому критерий честно
  пишет «домен не проверен»;
- формат — совпадение метки hh с `basics.formats`; отсутствие метки считается
  неизвестным (половина веса), а не провалом;
- опыт — стаж от начала веб-опыта в резюме против требования hh;
- зарплата — верх вилки против пожелания; нет вилки или другая валюта —
  неизвестно, половина веса.

## Письма

```powershell
pnpm hh:letters   # письма для вакансий, прошедших порог
```

Письмо собирается из данных резюме: заголовок, стек, факты из опыта. Три варианта
под типы вакансий — продуктовый, аутстафф и сервисная разработка; рекомендуется
тот, что подходит по заголовку, компании и описанию вакансии, а в базе лежит
рекомендуемый — остальные пересобираются из тех же данных. Длина — не больше
1700 знаков: hh жёстко поле не ограничивает, но советует 1000–1700, и это верхняя
граница. Почта, телефон и ссылки в письмо не попадают, цифры — только из резюме
и вакансии.

Вариант можно переключить в карточке очереди: выбор человека запоминается
(`Letter.selectedAt`), и повторный `pnpm hh:letters` его не перетирает.

## Очередь ревью

```powershell
pnpm dev   # http://127.0.0.1:3000
```

Страница показывает вакансии, прошедшие порог: оценку с причинами по критериям,
готовое письмо, переключатель варианта и ссылку на hh. Кнопки «Одобрить /
Отклонить» пишут статус в `Application`, «Отправить сейчас» отправляет одну
одобренную карточку. Дневной лимит — 20 откликов, он же верхняя граница счётчиков.
API: `GET /api/queue`, `POST /api/queue/decision`, `POST /api/queue/letter`.

## Отправка откликов

Отправка идёт через интерфейс hh в браузере: инструмент открывает вакансию,
нажимает «Откликнуться», вставляет письмо и отправляет форму — как человек.
Внутренние эндпоинты и обход капчи не используются.

Предохранители — часть контракта, а не настройки:

- выключатель `HH_AUTO_APPLY` — без него прогон сухой: печатает план и ничего
  не нажимает. Включение только вручную и на ограниченное время;
- 20 откликов в день (`DAILY_APPLICATION_LIMIT`), граница — московские сутки;
- окно 10:00–19:00 МСК по будням: суббота и воскресенье — остановка;
- пауза 45–150 секунд между откликами со случайным сдвигом;
- капча или истёкший вход (`HhBlockedError`) — статус `needs_human`, прогон
  останавливается, следующая карточка остаётся в `approved`;
- panic — `POST /api/apply/panic` поднимает флаг, прогон останавливается на
  ближайшей проверке (между откликами и во время паузы); `DELETE /api/apply/panic`
  снимает флаг;
- повторный прогон не дублирует отклик: в работу попадают только `approved`.

```powershell
pnpm hh:apply             # сухой прогон, если HH_AUTO_APPLY выключен
pnpm hh:apply --dry-run   # принудительно сухой
pnpm hh:apply --limit 3   # живой прогон не больше трёх откликов
```

Из UI то же самое: панель «Отправка откликов» (сухой прогон, запуск, «Стоп
(panic)») и кнопка «Отправить сейчас» в одобренной карточке. Кнопка работает и
при выключенном `HH_AUTO_APPLY` — это явное действие человека, но окно, дневной
лимит и panic действуют и для неё.

API: `GET /api/apply` (состояние окна, лимита, panic и последний прогон),
`POST /api/apply` (запуск), `POST /api/apply/send` (одна карточка),
`POST /api/apply/panic` и `DELETE /api/apply/panic`. Каждое действие и каждая
остановка пишутся в `ActionLog`, прогон — в `Run` со статистикой.
